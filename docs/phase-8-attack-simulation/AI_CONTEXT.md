# Phase 8 — AI Context

## Original spec goal

> Reproducible scripts that generate labelled attack + benign traffic
> against the local API. This is our own test harness — no external
> targets, satisfies the ethics disclaimer.

## Tasks (as written, `attack-sim/`)

1. `sqli_attack.py`: send a variety of SQLi payloads (union-based, boolean
   `OR 1=1`, comment, obfuscated/encoded) to `/api/search/vulnerable`.
2. `brute_force.py`: rapid-fire `/api/auth/login` with one username and
   many passwords.
3. `credential_stuffing.py`: many `(username, password)` pairs from a
   **synthetic** list we create ourselves (never real leaked data).
4. `benign_traffic.py`: realistic normal traffic (valid logins, normal
   searches, browsing).
5. Each script records what it sent + expected label to a CSV for scoring
   in Phase 9.

## Deliverable check (as written)

Running each script produces requests the stack classifies; results
logged. Benign traffic mostly passes; attack traffic mostly blocked.

## Suggested commit message (as written)

`feat: attack simulation and benign traffic generators`

## Ethics constraint (must not be violated)

All attack traffic is generated by our own scripts against our own local
API only. Credential-stuffing pairs must be synthetic, never real leaked
data.

## Status

**Complete.** Four generators, a sequenced runner, and a recalibration tool.
The benign traffic recalibrated the detection strategy and exposed the Phase 6
false-positive blocker as an auth-endpoint problem: the payload classifier
scored credential bodies as attacks. Fixed by scoping ML to payload-bearing
endpoints (`config.mlPayloadPaths`). Benign FPR 17.5% -> 1.8%, SQLi still 100%,
behavioural attacks now caught by the rules at attempt/username 5 rather than by
the ML artefact at 1. See IMPLEMENTATION.md.
